ADSBee m1421: sweep the LR2021 FIFO every 4 ms

Bench A/B against main, t-0413, 2026-10-13. m1421 on an ADSBee 1421 Programmer, cabled to a signal generator.

Result. The LR2021 can miss a preamble while it serves an SPI command, and main polls the FIFO level about 1,900 times a second. Starting a sweep at most every 4 ms cuts the SPI frames from about 2,500 to 400 a second and decodes more at every rate: +0.23 (+0.17 to +0.28) points at 500 frames/s, +0.28 (+0.21 to +0.34) at 1,000, +0.16 (+0.08 to +0.24) at 2,000, +0.27 (+0.14 to +0.41) at 4,000 (95 % intervals, paired by burst). No FIFO overflow, no packet lost after reception, UAT unaffected.

Method

256-frame bursts with sample-exact start times, 3 DF17 to 1 DF11, ICAO 0xADF000 to 0xADF0FF, exponential spacing with a 140 µs floor, −50 dBm unless stated. One test image built from main with the sweep policy switchable at run time; every burst is sent once per policy, order rotated, and differences are paired by burst with bootstrap intervals. The PR image and a main image as built were then flashed in turn and run on the same bursts.

The gain levels off at 4 ms. "Every n-th main-loop pass" was also tried (n = 2, 3, 4): a sweep already spans several passes, so n = 2 and 3 changed nothing and n = 4 gave no measurable gain. A packet now waits up to 4 ms in the FIFO before it is read (0.5 ms on main); the measured time between sweep starts was 4.0 ms on average and 5.1 ms at most.

Not tested

  • Live sky (the module is cabled; a few frames of real traffic leaked in during one minute and those bursts were dropped for both policies).
  • UAT and 1090 on the air at the same instant; the DF17 preamble mode; other units; temperature.

Bench state

Feeds: the m1421 has no network path and reported only to the test script. The 1090U on the same Pi is cabled to a different generator and has Ethernet and Wi-Fi station off. No feed could carry the synthetic frames. Maximum level into the module −20 dBm. The LR2021 never transmitted.
