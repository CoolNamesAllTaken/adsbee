ADSBee MLAT server core: validation

Simulated traffic (adsbee_mlat_sim), 50 aircraft within 150 km, 40 % without ADS-B, 180 s per scenario, first 30 s left out. Every message heard by two or more synchronized receivers updates the aircraft's track (all aircraft are tracked here, also the ADS-B ones, so their GNSS positions serve as truth). Receivers on a ring 30 km between neighbors, plus one in the center from 5 receivers on.

The 48 and 12 MHz curves of the ADSBee 1090 nearly coincide: with this error model the per receiver and aircraft biases, clock sync and geometry outweigh the counter resolution. See the timestamp study (t-0429) for the error budget.

"Inside reported error": share of fixes whose true horizontal error is below the published err_m (about 65 % is the goal for a one sigma estimate; with few receivers the estimate is optimistic by up to 1.4 times). Three receivers locate aircraft only where the solution is unique; outside the array a fix with three receivers and altitude has a mirror solution, which the server detects and skips, but the tail shows some mirror tracks remain. Use four or more receivers.

Update rate

Fixes are not resampled: each Mode S reply, all-call reply or squitter heard by two synchronized receivers moves the track, so an aircraft is updated as often as it transmits (here 2 to 12 messages per second each).

Latency

Latency is set by the grouping window (0.3 s), the time the server waits for copies of a message from all receivers. Fixes below it are repeated identical replies that joined a window already open.

Real-time run, 5 receivers streaming Beast with receiver info frames over TCP for 120 s: 5,449 MLAT fixes and 8,351 ADS-B positions published. MLAT latency median 318 ms, 95th percentile 330 ms. Published MLAT fixes (Mode S only aircraft): median horizontal error 98.9 m, 95th percentile 549 m, median rate 3.2 per second per aircraft.

Throughput

50 receivers spread over a 100 km radius, 400 aircraft within 250 km: about 2,000 messages per second per receiver, 100,000 in total, each message heard by about 40 receivers. Beast parsing alone runs at 1,409,261 messages per second on one core.
